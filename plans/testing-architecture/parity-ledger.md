# Testing architecture parity ledger

> Purpose: track coverage parity while migrating from `tests/unit_tests` and `tests/integration_tests` to the target layered test layout. Do not delete or disable any legacy test file until every entry for that file is terminal.

## Status model

- `pending`: legacy case still owns coverage.
- `rewritten`: target test preserves or broadens the legacy invariant; a byte-identical relocation into the correct target lane also qualifies.
- `split`: legacy case was split across multiple target tests; assertion groups are named in the evidence.
- `retired`: legacy case was intentionally removed as obsolete or redundant; the reason is recorded.

A migration PR that deletes or disables a legacy file must update all of that file's entries to `rewritten`, `split`, or `retired` in the same commit. For mixed cases, preserve assertion groups explicitly in the evidence notes before marking the entry terminal.
